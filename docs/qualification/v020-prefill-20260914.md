# v0.2.0 prompt-processing benchmarks

Measured on 2026-09-14 on the dual Radeon AI PRO R9700 workstation. Both profiles ran from the public **v0.2.0** source (`9bd62ad7d800fc6378da6997533ff5c9a23f2ddc`) and their released images, using their already-qualified public placements. Original model, head and PLE files were unchanged.

The procedure reproduces the original release’s [sustained PP suite](results/qwen38-group16-pp-v1.json), including the 1K warmup recovered from its original raw records. The script is byte-identical to the [August release checkpoint](https://github.com/Dyluhn/R9V/blob/792fde0f6183dfb3487cca2e734958e6664a711a/scripts/bench-pp.py). Each profile used one startup, one unmeasured 1,024-token/one-output warmup, then ten 8K/one-output requests (one-second pauses), three 32K/16-output requests (two-second pauses), and two 64K/16-output requests (two-second pauses). Requests were serial.

| Current profile | 8K mean / median | 32K mean / median | 64K mean / median | All trials |
|---|---:|---:|---:|---|
| IQ4_XS | 989.3 / 984.6 | 982.0 / 984.7 | 968.2 / 968.2 | [JSON](results/iq4-v020-pp-20260914.json) |
| Q4_K_XL | 552.9 / 549.4 | 542.5 / 544.4 | 536.4 / 536.4 | [JSON](results/q4-v020-pp-20260914.json) |

Both profiles keep MTP4 and a 131,072-token context reservation. IQ4 image7 uses 76/451 static experts and 160/0 cache slots across ranks; Q4 image6 uses 99/348 static experts and 80/0 cache slots. Exact image IDs and runtime settings are recorded in each JSON.

Current IQ4 means are 34.6%, 30.0%, 28.7% lower than the original IQ4 reference at 8K, 32K and 64K, respectively.

Rates are prompt tokens per second, computed independently for every request as `prompt_tokens / TTFT`. The script marks TTFT at the first streamed output-token event, including tokens that decode to empty text. It obtains actual prompt lengths through `/tokenize`; unique nonce prefixes prevent prefix reuse. Prefix-cache hit counters were zero throughout both matrices. The last 8K corpus slice can be slightly shorter than 8,192 tokens; the JSON records the actual count and every timing.

The original IQ4 MTP2 reference means were **1,512.0 / 1,401.8 / 1,357.0** tok/s at 8K/32K/64K. The table above measures the current MTP4 runtime and current placements. It does not isolate the cause of a difference between releases. These are PP measurements, not new decode throughput or quality scores. The two-trial 64K sample does not establish tail latency.

The initial IQ4 series was started before the original 1K warmup record was recovered. That series was preserved as preliminary and excluded; the reported IQ4 series includes the recovered warmup. Both reported runs stopped cleanly, reclaimed their GPU allocations and completed at least 90 seconds of monitoring. Complete evidence archives, including the released source, compiled caches and runtime logs, were independently verified on both hosts; public JSON contains all measured trials and archive commitments.

## Reproduce

Use the [public v0.2.0 source](https://github.com/Dyluhn/R9V/releases/tag/v0.2.0) and follow its setup instructions. Start either `qwen38-mtp4` (IQ4) or `qwen38-q4-xl` (Q4). Use an idle server and run the following once for each profile, serially. Keep the current released MTP4/profile settings; do not substitute the old MTP2 runtime.

```bash
# Run from the v0.2.0 repository root with the selected server ready.
BENCH_URL=http://127.0.0.1:8004
BENCH_OUT=pp-results
mkdir "$BENCH_OUT"
curl -fL https://raw.githubusercontent.com/Aider-AI/aider/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/tests/fixtures/chat-history.md -o "$BENCH_OUT/chat-history.md"
echo "a9a89dfd830af253103f86ff25dcba55364b22db779664d2fb36a3c2fd058710  $BENCH_OUT/chat-history.md" | sha256sum -c -

python3 scripts/bench-pp.py "$BENCH_OUT/chat-history.md" --url "$BENCH_URL" \
  --target-tokens 1024 --runs 1 --max-tokens 1 --pause-seconds 0 \
  --output "$BENCH_OUT/warmup-1024.json"
for row in "8192 10 1 1" "32768 3 16 2" "65536 2 16 2"; do
  read -r target runs output_tokens pause <<< "$row"
  curl -fsS "$BENCH_URL/metrics" > "$BENCH_OUT/pp-$target-before.prom"
  python3 scripts/bench-pp.py "$BENCH_OUT/chat-history.md" --url "$BENCH_URL" \
    --target-tokens "$target" --runs "$runs" --max-tokens "$output_tokens" \
    --pause-seconds "$pause" --output "$BENCH_OUT/pp-$target.json"
  curl -fsS "$BENCH_URL/metrics" > "$BENCH_OUT/pp-$target-after.prom"
done
```

Use a separate output directory for each profile. Retain every trial and check actual token counts, prefix-cache counters and runtime health before comparing summaries. Benchmarking settings do not remove the release’s normal setup, qualification or memory guards.

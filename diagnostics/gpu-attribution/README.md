# GPU attribution campaign

Records named asynchronous GPU dispatches and completion callbacks, with original ELF code objects saved at load time and independently verified on blackbox. Queue identifiers are not PASIDs. Root DRM/KFD process identity history supplies ownership evidence.

No debug agent or live wave/register capture is enabled: the installed debugger cannot attach both workers with the current integrated GPU topology. No device is removed or rebound. MEMORY_COPY callbacks are disabled because the installed SDK aborts during RCCL async-copy timestamp processing. Kernel dispatch callbacks remain enabled.

Admission requires the current boot, independent recorder heartbeats, root identity receipt, and two-worker arithmetic plus RCCL allreduce smoke. CPUinfo subprocess output and external stdout/stderr line assembly are checked. The transport preserves complete records without changing application stdout. Sequence gaps, missing ELF capture, budget violations, first faults and decode stalls stop the campaign after evidence is frozen.

Model startup allowance is 1800 seconds; the total workload remains bounded to 5400 seconds. Route collection remains off and original image and placement are preserved. Assets are limited to 2 GiB and all campaign data to 4 GiB per machine. No automatic reset, power cycle or retry is implemented. Capturing dispatches can change timing; an instrumented pass alone does not establish a fix.

Campaign assembly must preserve executable modes (copy metadata before editing text) and verify `baseline-source/scripts/launch.sh` is executable. Copy `serving_capture.py` and `line_stream.py` into the mounted campaign. The sustained harness invokes `python3 /capture/serving_capture.py`, requires both actual ranks in the independently acknowledged dispatch PID set, and must not retain a debugger-library admission requirement. The frozen controller runs Docker log following through `line_stream.py` on the workstation. The live smoke exercises the same serving identity helper before a model launch.

Regression checks: `python3 -m unittest test_capture test_line_stream test_serving_capture test_live_trace -v` from this directory. Nine tests passed on September 10. The campaign also validated its 54-request CPU fixture and freeze-before-stop controller fixture; those are not GPU stability results.

Known model limitation found September 10: the first profiled serving request accumulated 20,000 unmatched enqueue notifications on rank 0, despite later same-queue completion callbacks. A separate two-worker 80,004-dispatch arithmetic control completed with zero missing callbacks. This model result is not a proven GPU hang and is not fixed by the source capture repairs. Do not claim a complete model unfinished-operation set from this profiler configuration. The subsequent 161500 campaign deliberately uses identity-only capture to resolve first graphics-timeout ownership under original unprofiled execution.

The unprofiled 161500 campaign reproduced the real gfx_0.0.0 timeout on 0000:03:00.0. Root fdinfo sampled 74 ms before the timeout maps PASID 64 to Xwayland host PID 3496; inference workers have different PASIDs. This identifies the owner of the timed-out graphics job, not the initiating cause. The GPU subsequently disappeared from the bus. Recovered local request history shows 34 requests completed and request 34 active at the fault; the last remote checkpoint (request 33 start) was stale.

Graphics follow-up 165200 retains unprofiled inference and adds Xwayland-only `GALLIUM_DDEBUG=5000`, without the `flush` option. Draw state, decoded GPU packets and shader disassembly were verified on installed Mesa 26.1.6. Hang dumps and Xwayland journal records are received on blackbox. The wrapper is boot scoped and expires; remove it and its artifact-directory compatibility symlink after capture. This campaign is still diagnostic, not a validated fix. Frozen campaign sources and exact configuration are under the incident AI-Work root.

Do not deploy the installed Mesa 26.1.6 Gallium debugger for this campaign: a recovered Xwayland core proves that DDEBUG leaves `pipe_context.resource_release` unset. During `st_prune_releasebufs`, the state tracker calls that null pointer. The 165200 Xwayland SIGSEGV is therefore an instrumentation defect; it does not explain the uninstrumented 161500 hang. A later Plasma-owned graphics timeout and bus loss were retained separately. The temporary wrapper was removed. CPU core, GDB proof and cleanup records are in incident `recovery-20260910T1717Z`.

The medians for the matched first 17 stress requests were 54.77 and 51.89 token/s,
respectively. All stress requests generated 512 tokens. The test alternated short,
roughly 8K-token and roughly 61K-token prompts with 15-second idle periods. Both
arms also completed progressive context checks through 105K tokens. The reduced
stress window was shortened to retain time for restart within the overall bound.
The full configured 128K limit was not exercised.

The reduced container was stopped and restarted. Health returned within the
five-minute restart bound, and text, tools and vision passed again. Both test
containers were stopped afterward and retained for inspection.

Memory was sampled once per second from sysfs. These values can miss shorter
allocation peaks and do not distinguish live tensor allocations from allocator
reservations. Rank 1's model-loading figure dropped from 25.85 to 23.70 GiB;
physical free headroom improved by about 2.01 GiB during the tested workloads.
The payload accounting predicted 2.17 GiB less static residency.

Current-arm startup reduced available host RAM to 12.59 GiB before temporary
loading buffers were released. A steady-state cold-expert budget alone is not a
sufficient startup RAM check; this observation is not a universal RAM minimum.

## Failures and diagnostic findings

The first launch failed before model loading because rootless Docker could not
raise its inherited hard memlock limit to unlimited. The launcher now inherits
that policy under rootless Docker and retains the unlimited request for rootful
Docker. The actual corrected rootless launch succeeded. Four executable launcher
cases cover rootful/rootless behavior with internal/external manifests; the
19-test diagnostics suite and static checks passed.

PyTorch repeatedly logged `Object of type function is not JSON serializable`
while recording compilation/runtime metrics. Compilation and serving continued.
These traces must not be classified as serving crashes solely because they
contain error text. Cold compilation took about 152 seconds for a recorded model
compile step; the reduced arm loaded its AOT cache in a few seconds.

Runtime doctor failed both cards' headroom checks for the current arm. After the
reduced arm's restart and short functional checks, it failed the display card
only. The earlier stress timeline nevertheless showed rank 1 below 3 GiB. An idle
or lightly loaded doctor snapshot cannot certify worst-case headroom.

Startup metrics-unavailable events and the deliberately requested restart were
separated from serving failures. No request failure, unexpected stall, new OOM,
or unexpected PCIe-error event was recorded during the tested serving intervals.

## Next changes

1. Reduce residency on **both** cards when targeting 3 GiB headroom on this host.
   A `300/320` map is a reasonable next experiment based on the measured deficit
   and packed expert costs; it has not been tested and is not a qualified default.
2. Measure allocated/reserved/free VRAM inside the actual workers during loading,
   vision, prefill, decode and graph capture. Use those measurements in the
   headroom planner and readiness gate.
3. Make loading/compilation progress visible and qualify restart latency with the
   available host RAM recorded alongside it.
4. Investigate the current throughput gap and compilation-metrics errors separately
   from the reported intermittent crashes. Compare ROCm 10 as a separate candidate.

No default placement was changed, no image was published, and no qualification
status was promoted. Local evidence includes per-request outputs, startup/server
logs, one-second memory samples, five-second runtime captures, metrics before/after
each arm, doctor reports and support bundles. Raw evidence remains outside Git.
